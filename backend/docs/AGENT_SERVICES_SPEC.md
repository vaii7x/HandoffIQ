# Agent Services Integration Specification for AI Developer

## 1. Overview

HandoffIQ coordinates an asynchronous multi-agent pipeline:
`Task Registration` → `Researcher` → `Handoff Validation` → `ContextMap` → `Coder` → `Reviewer` → `Tester` → `Recovery Decision` → `Verification`.

This document defines the 4 agent service interfaces that the **AI Developer** must implement and inject. The backend provides clean abstract contracts in `app.services.agents.base`.

---

## 2. Agent Service Interfaces

### 1. Researcher Service (`ResearcherService`)
Analyzes the user's task prompt and canonical requirements to create an initial technical design and handoff payload.

```python
from app.services.agents.base import ResearcherService, ResearchInput, ResearchOutput

class GeminiResearcherService(ResearcherService):
    @property
    def name(self) -> str:
        return "gemini_researcher"

    async def execute(self, input_data: ResearchInput) -> ResearchOutput:
        # Access: input_data.task_id, input_data.original_request, input_data.requirements
        # Execute Gemini prompt to analyze architecture and specifications...
        return ResearchOutput(
            summary="Architecture and design breakdown generated by Gemini.",
            handoff_payload={
                "architecture_spec": "...",
                "components": ["Auth", "Dashboard", "API"],
                "data_models": "...",
            },
            requirement_ids=[r.id for r in input_data.requirements],
        )
```

### 2. Coder Service (`CoderService`)
Generates code artifacts implementing the canonical requirements according to the structured context map.

```python
from app.services.agents.base import CoderService, CoderInput, CoderOutput
from app.models.artifact import CodeArtifact

class GeminiCoderService(CoderService):
    @property
    def name(self) -> str:
        return "gemini_coder"

    async def execute(self, input_data: CoderInput) -> CoderOutput:
        # Access: input_data.task_id, input_data.requirements, input_data.context_map
        # Generate code files...
        artifacts = [
            CodeArtifact(
                task_id=input_data.task_id,
                path="src/App.tsx",
                language="typescript",
                content="...",
                requirement_ids=["R001"],
            )
        ]
        return CoderOutput(
            artifacts=artifacts,
            summary="Implemented frontend components and API client.",
        )
```

### 3. Reviewer Service (`ReviewerService`)
Evaluates generated code artifacts against the canonical requirements, detecting implementation gaps or approving the implementation.

```python

from app.models.handoff import ValidationIssue, IssueType, IssueSeverity

class GeminiReviewerService(ReviewerService):
    @property
    def name(self) -> str:

    async def execute(self, input_data: ReviewerInput) -> ReviewerOutput:
        # Access: input_data.task_id, input_data.requirements, input_data.artifacts
        # Review artifacts against requirements...
        return ReviewerOutput(
            approved=True,
            issues=[],
            review_notes="All code artifacts comply with security and architecture constraints.",
        )
```

### 4. Tester Service (`TesterService`)
Executes unit/integration tests or generates verification evidence against code artifacts.

```python
from app.services.agents.base import TesterService, TesterInput, TesterOutput
from app.models.test_result import TestResult, TestStatus

class GeminiTesterService(TesterService):
    @property
    def name(self) -> str:
        return "gemini_tester"

    async def execute(self, input_data: TesterInput) -> TesterOutput:
        # Access: input_data.task_id, input_data.requirements, input_data.artifacts
        # Run test suites or generate verification proof...
        test_results = [
            TestResult(
                task_id=input_data.task_id,
                requirement_ids=["R001"],
                test_name="test_auth_flow",
                tool="pytest",
                status=TestStatus.passed,
                output="1 passed",
                duration_ms=45,
            )
        ]
        return TesterOutput(
            test_results=test_results,
            all_passed=True,
            summary="All tests passed with full requirement coverage.",
        )
```

## 3. Evidence-Based Verification Rule

> [!IMPORTANT]
> The backend verification stage strictly obeys the evidence-based requirement rule:
> - A requirement is marked `RequirementStatus.verified` **only** if linked to passing `TestResult` records.
> - If any test for a requirement fails, the requirement is marked `RequirementStatus.failed`.
> - If no test covers the requirement, it remains `implemented` or `awaiting_review`. It is never verified without evidence.

## 4. Injecting Services into HandoffIQ

When ready, inject the live AI services at application startup:

```python
from app.services.agents import (
    set_researcher_service,
    set_coder_service,
    set_reviewer_service,
    set_tester_service,
)
from your_ai_agents import (
    GeminiResearcherService,
    GeminiCoderService,
    GeminiReviewerService,
    GeminiTesterService,
)

set_researcher_service(GeminiResearcherService())
set_coder_service(GeminiCoderService())
set_reviewer_service(GeminiReviewerService())
set_tester_service(GeminiTesterService())
```

When `MOCK_MODE=false`, calling any uninjected mock service will immediately raise `ConfigurationError` to prevent silent execution of fake results.
